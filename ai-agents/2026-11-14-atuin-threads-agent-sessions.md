# Atuin Threads：把 Claude Code、Codex、OpenCode 的会话记录同步到每台机器，还能换个代理接着做

**一句话结论**：命令行历史工具 Atuin 从 18.24 版起加了 Threads 功能，能搜索、同步各台机器上的 AI 代理会话，在一台机器上用 Claude Code 开的头，可以到另一台机器上用 Codex 接着做；同时带一个 MCP，让代理自己去翻以前的会话。好用，但等于把所有会话（里面可能有密钥）集中到一处，要先想清楚。

## 要点

- **支持哪些代理**：目前是 Claude Code、Codex、Pi、Omp、OpenCode，作者说后面还会加。
- **怎么用**：安装或升级到 Atuin 18.24 以上，运行 `atuin resume` 打开一个终端界面，挑一个会话恢复，或者把它“分叉”到另一个代理里继续。
- **MCP**：`atuin mcp install` 可以给 claude、codex、pi、opencode 自动装上，装好后代理能自己搜以前的会话，比如找到之前做过一半又放弃的方案和放弃的原因，不用你再写一遍需求。
- **同步和加密**：同步时端到端加密，官方托管的同步服务器读不到内容；也可以自建同步服务器，或者完全只存在本机。记录代理会话要自己开启，默认不收。
- **作者举的例子**：一台测试机性能差，代理怀疑是磁盘慢，就把会话分叉到 SSD 更快的笔记本上继续测，测完原机器上的会话再把结果拉回来写修复，中间不用手动复制任何东西。
- **团队共享**：作者说在做可选的团队会话共享，还没上线。

## 适合谁

- 同时在好几台机器（本机、VPS、云开发机）上跑 Claude Code、Codex、OpenCode，经常想不起“上次那个问题是在哪台机器、哪个代理里解决的”的人。
- 想让代理之间互相参考历史会话，减少重复踩坑的人。

## 注意事项

- **会话里常有密钥**：代理会话会记下它执行过的命令和输出，里面可能有密码、token、连接串。HN 上有人专门花了几个月把各个代理互相隔离、定期扫会话里泄露的凭据，明确表示不会用这个功能。开之前先确认会话里没有明文密钥，或者只在本机用、不开同步。
- **在意隐私就自建同步服务器**：虽然官方说端到端加密，把所有命令历史和代理会话放到别人的服务器上，还是有人不放心。Atuin 本来就支持自建同步服务。
- **token 消耗**：有评论担心代理用 MCP 去读以前的会话会多花 token，这一点文章没给数据，要自己观察。
- 本条只整理了官方博客和 HN 讨论，没有实际安装测试。
